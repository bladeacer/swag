# v1.1.0: performance and the smaller fixes

The second performance release. It cuts the allocations of every reader and every writer, streams the plain readers, and adds three external tools to the benchmark suite. [The performance audit](../performance.md) records the numbers.

## Added

- `envelope.Read`, a streaming reader for the plain formats. It passes one line at a time to a handler and stops at the integrity block, so the SubRip and the SBV readers hold no slice of the whole file.
- `model.RubyGroupsInto`, a grouping that writes into a caller slice. The writers reuse one backing array for the whole document, so a render builds no slice for each cue.
- `make bench-hyperfine`, `make bench-strace`, and `make bench-perf` measure the release binary with the external tools. `make bench-tools` runs all three, and `make bench-audit` adds the CPU profile and the execution trace.
- `scripts/bench-fixture.sh` writes the ten-thousand-cue SubRip fixture that every external tool measures, so the tools agree on one document.

## Changed

- Every writer reserves its output buffer from the cue count. A large render grows the builder once, so the bytes of a render fall by more than half in most formats.
- The SubRip span splitter appends into the span slice of the cue, the SubRip counter test skips the parser on a text line, and the SubRip and SBV timestamp parsers find the colons instead of splitting the string.
- The YouTube reader pre-sizes its cue list and its three scratch slices, so the shared YTT and SRV3 path grows them at most once.
- The WebVTT reader reads its lines through `envelope.ReadLines`, so the two copies of the line scanner become one. The cue parser needs random access, so this reader keeps the whole list.

## Notes

- The SubRip parse allocates half as many objects, and the render of every format allocates about ten thousand fewer objects.
- The module keeps 100 percent statement coverage.
- A hand-written configuration reader stays a candidate for a later release. The current decoder spends its time in reflection, because the TOML library reads the whole file and then parses it.

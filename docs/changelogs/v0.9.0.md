# v0.9.0: configuration, compatibility, and the release candidate

This release carries the settings of a user between runs and turns the integrity block off on request. It reads its default locale from the system. It adds the interactive keybinds, the parallel batch conversion, and the frozen public API that v1.0.0 will keep. It is the release candidate for v1.0.0.

## Added

- The interactive keybinds, with a leader key and multi-key chords. The built-in bindings are `<leader>a` for the default answer, `<leader>?` for the keys, and `<leader>q` to quit without a write, and the leader is `ctrl+x`. A modifiers joins with `+`, so `ctrl+shift+r` is one key. The `keybinds` table of the configuration file moves a binding or removes it with an empty value. [The configuration page](../configuration.md) records the notation.
- `internal/tui.NewKeymap` and the key notation parser. An action that the mode does not run is an error. So is a pair of bindings that name the same keys, so a typo never leaves a binding inert. [The testing notes](../testing.md) name the suite.
- The system locale detection for the message catalogue. The command reads `LC_ALL`, then `LC_MESSAGES`, then `LANG`, in the order of the POSIX standard. It drops the codeset and the modifier from the value. The first tag that a catalogue carries selects the locale, and `en-US` is the fallback. [The internationalisation page](../i18n.md) records the order.
- The `--jobs` flag, with the short form `-j`, which sets how many conversions of a batch run execute at once. The default keeps two cores free, a named count sets the worker count, and zero uses every core. A negative count is an error. The report does not depend on the count, because the first failure is the first file in the walk order. [The usage page](../usage.md) records the flag.
- The `jobs` setting of the configuration file, which carries the same value as the flag.
- [The compatibility page](../compatibility.md). It records the six release targets with the evidence of each, the specification that every reader follows, and the players that document each format.
- The API stability section of [the library guide](../library.md). The public surface of `pkg/sub` is frozen as of this release, and no name carries a deprecation note.

- The TOML configuration file. It carries the locale, the default flags (`verbose`, `strict`, and `strict_compat`), the flag options (`font`, `from`, and `format`), the preferred formats, and the keybinds table. The command line wins over the environment, the environment wins over the file, and the file wins over the built-in default. Kong applies the file through a resolver, so a setting fills only a flag that the command line left unset. An unknown key is an error, so a typo never passes in silence. [The configuration page](../configuration.md) records the schema and the precedence.
- `swag config --init`, with the short form `-i`. It writes the commented default file to the resolved path and creates the directory. The command refuses to replace an existing file, and the written file carries every setting as a comment, so writing it changes no behaviour.
- The `preferred` list. A batch run with no `-f` flag writes those formats in order, and the interactive target question offers them first.
- `internal/config` now decodes the file. [The configuration page](../configuration.md) carries the same content as the documented sample, and a test keeps the two in step.
- The `--strict-compat` flag of the `convert` and `interactive` commands, with the short form `-c`. The write drops the integrity block, so the output holds the plain cues and stays inside the original specification of the target format. The loss report stays complete, because the read keeps every feature that the input carries. [The usage page](../usage.md) records the flag, and [the integrity page](../integrity.md) explains the block.
- `pkg/sub.Options.StrictCompat`, the library form of the flag. A strict write renders into memory first and removes the block before it reaches the sink. [The library guide](../library.md) covers the option.
- `internal/envelope.Strip`, which removes either block form from rendered output. It handles the plain form at the end of a file and the XML comment form inside an element. [The testing notes](../testing.md) name the suite.

## Changed

- `swag config` reports the resolved location of a present file as the tool reads it. The earlier wording promised a later release.
- A failed command now reads `The command failed.` rather than `Conversion failed.` The `config` command can fail too, so the message names every command.
- The default locale is now `en-US`, and the tool reads the system locale first. A machine set to British English still reads `en-GB`, and a machine with no match reads `en-US`. [The internationalisation page](../i18n.md) records the order.
- The `--locale` flag carries no built-in value now, because the system locale decides. Pass `--locale` or set `SWAG_LOCALE` to name a locale.
- The British catalogue is now the smaller one. The default catalogue in [the i18n package](../../internal/i18n/i18n.go) carries every key, and [the British catalogue](../../internal/i18n/en_gb.go) carries the entries whose wording differs.

## Notes

- `--strict-compat` is off by default. A plain reader outside `swag` ignores the block and reads the cues, so a file that keeps the block stays useful.
- `--strict-compat` and `--strict` are separate. The first one removes the block, and the second one fails a conversion that drops a feature. A run can set both.
- A missing configuration file changes no behaviour. The default file carries the settings as comments, so `swag config --init` is a safe first step.
- The `keybinds` table of the configuration file now takes action. The interactive mode reads it on every run.
- A batch run keeps its report whatever the worker count. The first failure is the first file in the walk order. It is not the first file to finish, so two runs over the same directory report the same failure.
- A snapshot covers the six native targets, and the checksums file covers each archive. The `js/wasm` build stays skipped, because the browser demo lands with v1.0.0.
- The interactive mode reads one answer per line, so it works on a pipe as well as on a terminal. The keybinds are a layer over those prompts and not a full-screen input widget.
- The documentation sweep of this release covers the prose of every page under `docs/`. It split or rewrote 41 sentences that ran over the 25-word limit, and the list items around them, and it left every fact unchanged. Most of the findings sat in the format notes.

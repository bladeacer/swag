# v0.7.0: library hardening and format integrity

This release widens the conversion report, proves that the readers and the writers compose, and hardens the public library. It adds a configured conversion API, a fuzz target for every reader, benchmarks for a large document, a second locale, and the reference docs.

## Added

- `pkg/sub.ConvertWith` with an `Options` value. The options carry the input format, the target format, a style mapping, a font override, and a `LossPolicy` of `LossReport`, `LossStrict`, or `LossSilent`. `pkg/sub.Convert` delegates to it.
- Loss notes in the YTT, SRV3, SRT, and SBV writers for a strikeout run and a glyph scale.
- A cross-check case that runs the override fixture through every shipped writer. It asserts the exact loss report of each target.
- A chain suite that runs one fixture per reader through a sequence of formats of length two or more, then back to the source format. It asserts that the text and the cue timing survive, so the readers and the writers compose.
- A fuzz target for every reader in `pkg/sub/fuzz_test.go`, and [the nightly fuzz workflow](../../.github/workflows/fuzz.yml). Each target parses an arbitrary string and renders the result as JSON1.
- Benchmarks for a document with ten thousand cues, covering the parse, the render, and the conversion of every format, with a `benchstat` comparison workflow.
- The French message catalogue in `internal/i18n/fr.go`. Every runtime message of the CLI comes from the catalogue, and a test keeps the second locale in step with the default one.
- The `--font` and `--strict` flags of `swag convert`, which reach `ConvertWith`.
- [The library usage guide](../library.md): the public API with a worked example.
- [The testing notes](../testing.md): coverage, fuzzing, and benchmarks.

## Changed

- The ASS writer writes a glow shadow through the border colour and every other kind through the shadow colour, so a soft shadow and a bevel keep a visible shape and a glow no longer costs a loss. A span with more than one non-glow shadow reports a loss, because ASS carries one shadow channel.
- [The ASS support page](../ass-support.md): the deliberate loss list loses the chroma and vertical entries, and the test list names the new suites.
- [The format notes](../formats.md): the ASS loss list and the plain format loss lists name the new cases.
- The cross-check suite now covers every shipped writer, including the WebVTT, TTML, Kdenlive, and JSON1 writers.

## Fixed

- The ASS reader no longer crashes on a `\t` tag with two arguments. The argument list carries no timing in that form, so the reader keeps the values as tags.
- The ASS writer no longer reports a chroma loss when the offsets form the symmetric spread that the argument form rebuilds. A chroma that came from ASS round-trips without a loss.
- A blank `\ytvert` returns a run to horizontal text. A run that leaves vertical text no longer reports a loss.

## Notes

- A karaoke gap, a ruby base with several readings, a cursor with no text, and a shadow list with several entries stay out of the ASS writer, because ASS has no tag for them.
- The command line help text from kong stays in English until a later release. Every runtime message is localised.

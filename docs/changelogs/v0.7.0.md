# v0.7.0: library hardening and format integrity

This release keeps a document whole across a conversion, widens the conversion report, proves that the readers and the writers compose, and hardens the public library. It adds a configured conversion API, an integrity block for the plain formats, a version chain for the exchange format, a voice span, a fuzz target for every reader, benchmarks for a large document, a second locale, and the user guide.

## Added

- `pkg/sub.ConvertWith` with an `Options` value. The options carry the input format, the target format, a style mapping, a font override, and a `LossPolicy` of `LossReport`, `LossStrict`, or `LossSilent`. `pkg/sub.Convert` delegates to it, and the `--font` and `--strict` flags of the command reach it.
- `internal/envelope`: the integrity block of a plain format. SubRip and SBV writers append it when a write would lose a feature, and their readers restore the whole document from it. A three-way conversion through SubRip or SBV therefore returns the exact document, while a plain player sees plain subtitles.
- `model.TextSpan.Voice`, the speaker of a span. The WebVTT reader maps the `<v Speaker>` tag onto it, the WebVTT writer emits the tag, and JSON1 and the integrity block keep the name.
- The JSON1 version chain. The file shape moves to version 2 for the span voice, and the reader lifts a version 1 file to the current shape before it returns the document. A version with no step is an error.
- Loss notes in the YTT, SRV3, SRT, SBV, TTML, Kdenlive, and ASS writers for a voice name, because those formats have no voice form.
- Loss notes in the YTT, SRV3, SRT, and SBV writers for a strikeout run and a glyph scale.
- A cross-check case that runs the override fixture through every shipped writer. It asserts the exact loss report of each target.
- A chain suite that runs one fixture per reader through a sequence of formats of length two or more, then back to the source format. It asserts that the text and the cue timing survive, so the readers and the writers compose.
- A fuzz target for every reader in `pkg/sub/fuzz_test.go`, and [the nightly fuzz workflow](../../.github/workflows/fuzz.yml). Each target parses an arbitrary string and renders the result as JSON1.
- Benchmarks for a document with ten thousand cues, covering the parse, the render, and the conversion of every format, with a `benchstat` comparison workflow.
- The French message catalogue in `internal/i18n/fr.go`. Every runtime message of the CLI comes from the catalogue, and a test keeps the second locale in step with the default one.
- A voice span suite in `pkg/sub/voice_test.go` and an end-to-end conversion suite in `cmd/swag/main_test.go`. The second one walks the command line through every registered target and back.
- [The install page](../install.md), [the usage page](../usage.md), [the file integrity page](../integrity.md), [the JSON1 page](../json1.md), and [the internationalisation page](../i18n.md). [The format notes](../formats.md) gain the specification, the support, and the caveats and limits of every format.
- [The library usage guide](../library.md) and [the testing notes](../testing.md).

## Changed

- The plain format writers append the integrity block when a write would lose a feature. A document that fits in the plain format still writes no block, so a plain file stays plain.
- The JSON1 writer writes version 2 and the reader migrates version 1, so a file from the previous release opens with this one.
- The ASS writer writes a glow shadow through the border colour and every other kind through the shadow colour, so a soft shadow and a bevel keep a visible shape and a glow no longer costs a loss. A span with more than one non-glow shadow reports a loss, because ASS carries one shadow channel.
- The `convert` command is the default command with the `withargs` form, so its flags stand at the top level and the command word is optional.
- The success message ends with a newline, so the loss report starts on its own line.
- The loss lists of the format pages, the library guide, the readme, and the documentation index follow the code.
- [The ASS support page](../ass-support.md): the deliberate loss list loses the chroma and the vertical entries, and the test list names the new suites.
- The cross-check suite now covers every shipped writer, including the WebVTT, TTML, Kdenlive, and JSON1 writers.

## Fixed

- A bare run of the command prints the banner and the first step, and exits 0. `air` and `make run` therefore work without an input file.
- `swag -i in.srt -o out.sbv` works without the `convert` word, which the `default:"withargs"` form fixes. Before this release the top-level parser rejected `-i`.
- The air configuration uses `entrypoint` instead of the deprecated `bin` key.
- The ASS reader no longer crashes on a `\t` tag with two arguments. The argument list carries no timing in that form, so the reader keeps the values as tags.
- The ASS writer no longer reports a chroma loss when the offsets form the symmetric spread that the argument form rebuilds. A chroma that came from ASS round-trips without a loss.
- A blank `\ytvert` returns a run to horizontal text. A run that leaves vertical text no longer reports a loss.

## Notes

- A karaoke gap, a ruby base with several readings, a cursor with no text, and a shadow list with several entries stay out of the ASS writer, because ASS has no tag for them.
- The command line help text from kong stays in English until a later release. Every runtime message is localised.
- The integrity block is an extension of this project. A file that leaves `swag` stays a valid plain subtitle file.

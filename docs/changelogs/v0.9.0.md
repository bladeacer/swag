# v0.9.0: strict compatibility and the configuration file

This release adds the TOML configuration file, so the tool carries the settings of a user between runs. It also turns the integrity block off on request, so a conversion can stay inside the original specification of the target format. It adds the `--strict-compat` flag of the command line and the matching `StrictCompat` option of the library.

## Added

- The TOML configuration file. It carries the locale, the default flags (`verbose`, `strict`, and `strict_compat`), the flag options (`font`, `from`, and `format`), the preferred formats, and the keybinds table. The command line wins over the environment, the environment wins over the file, and the file wins over the built-in default. Kong applies the file through a resolver, so a setting fills only a flag that the command line left unset. An unknown key is an error, so a typo never passes in silence. [The configuration page](../configuration.md) records the schema and the precedence.
- `swag config --init`, with the short form `-i`. It writes the commented default file to the resolved path and creates the directory. The command refuses to replace an existing file, and the written file carries every setting as a comment, so writing it changes no behaviour.
- The `preferred` list. A batch run with no `-f` flag writes those formats in order, and the interactive target question offers them first.
- `internal/config` now decodes the file. [The configuration page](../configuration.md) carries the same content as the documented sample, and a test keeps the two in step.
- The `--strict-compat` flag of the `convert` and `interactive` commands, with the short form `-c`. The write drops the integrity block, so the output holds the plain cues and stays inside the original specification of the target format. The loss report stays complete, because the read keeps every feature that the input carries. [The usage page](../usage.md) records the flag, and [the integrity page](../integrity.md) explains the block.
- `pkg/sub.Options.StrictCompat`, the library form of the flag. A strict write renders into memory first and removes the block before it reaches the sink. [The library guide](../library.md) covers the option.
- `internal/envelope.Strip`, which removes either block form from rendered output. It handles the plain form at the end of a file and the XML comment form inside an element. [The testing notes](../testing.md) name the suite.

## Changed

- `swag config` reports the resolved location of a present file as the tool reads it. The earlier wording promised a later release.
- A failed command now reads `The command failed.` rather than `Conversion failed.` The `config` command can fail too, so the message names every command.

## Notes

- `--strict-compat` is off by default. A plain reader outside `swag` ignores the block and reads the cues, so a file that keeps the block stays useful.
- `--strict-compat` and `--strict` are separate. The first one removes the block, and the second one fails a conversion that drops a feature. A run can set both.
- A missing configuration file changes no behaviour. The default file carries the settings as comments, so `swag config --init` is a safe first step.
- The `keybinds` table of the configuration file is read, and it takes no action yet. The interactive keybinds land in this release, and they will read the table.

# v0.8.0: terminal UI and command line ergonomics

This release starts the terminal interface and cleans up the command line. It adds an interactive conversion command, with a renderer that repaints only what changed, a batch mode, and the colour and karaoke previews. It also adds an input format flag, a short form for every flag, and a themed banner. It adds the integrity block for WebVTT and TTML, and the platform configuration location. It also fixes the help page and the locale check.

## Added

- `swag interactive`, a command that asks for the input file, the target format, and the output file, then converts and shows the result. A value given on the command line skips its question, so `swag interactive -i in.ass -f vtt -o out.vtt` converts without a prompt.
- `internal/tui`, a renderer for a terminal frame. It holds the last frame and writes nothing when a frame is equal to it. When a frame differs, it repaints only the rows that changed, each at its own cursor position. It clears a row that the new frame leaves out. A still screen therefore costs no bytes, and a small change costs a small write.
- The `--from` flag, with the short form `-F` and the alias `--input-format`. It names the input format and skips detection, so a file with an unusual name converts.
- A short form for every flag. `-i` is the input, `-F` the input format, `-o` the output, `-f` the target format, and `-n` the font. The rest are `-s` for the strict policy, `-v` for the report, `-l` for the locale, `-V` for the version, and `-h` for the help. The aliases `--to` and `--input-format` join the long forms.
- The separator `--`. Every argument after it is a value, so a file name that starts with a dash still converts.
- The word `help`, which prints the help page, and the word `convert`, which stays optional. A bare help run names the commands first, so `swag --help` shows `interactive`, then the conversion flags.
- The XML integrity block of `internal/envelope`. The TTML writer appends the whole document inside an XML comment when a write loses a feature, and its reader restores the document. Every XML reader ignores a comment, so the file stays valid.
- Batch conversion. An input that is a directory converts every subtitle file under it, including the files in its subdirectories. The `-f` flag takes a comma-separated target list, so one run writes several formats at once. The `-o` flag names an output directory that the command creates. A progress bar counts the files, a failed file does not stop the run, and the command reports the failures and exits 1.
- `swag preview -i FILE`: the colour, style, and karaoke preview of a document. Each style takes a row with a colour swatch, the name, the font, the size, and the flags. A style with a box or an outline gains a second swatch. Each cue takes a row with its time range and its text, and a karaoke cue gains a bar underneath. The colours are a best effort, because a terminal that carries no colour shows the hex value instead.
- `internal/config`, the platform configuration location. It follows `$XDG_CONFIG_HOME` and the `$HOME/.config` fallback on Linux, `~/Library/Application Support` on macOS, and `%AppData%` on Windows. `SWAG_CONFIG_DIR` moves the directory and `SWAG_CONFIG` names the file.
- `swag config`, which reports the resolved configuration path, whether the file is present, and the platform of the build. The file format lands with v0.9.0, so the command creates nothing.
- [The configuration page](../configuration.md).
- The platform and architecture support in [the install page](../install.md): six release archives over Linux, macOS, and Windows on `amd64` and `arm64`
- The planned `js/wasm` target, and the note that any other platform builds from source because the code carries no cgo dependency
- The colour and karaoke preview builders in `internal/tui`: `Swatch`, `Tint`, `Hex`, `Clock`, `StyleRows`, `TimelineRows`, and `KaraokeBar`.
- The interactive result frame now carries the style rows and a short karaoke timeline, so the preview follows the conversion.
- The integrity block for WebVTT. A lossy write appends the `NOTE` block, which the format treats as a comment, and the reader restores the document.

## Changed

- The `en-US` catalogue replaces the French one. The project ships only the locales that a human has reviewed, and a translated locale arrives through machine assistance and a human audit. [The internationalisation page](../i18n.md) states the translation guidelines.
- The banner carries no background colour. The terminal theme decides how the title looks, so the title no longer paints a black bar.
- The success message ends with a newline, so the loss report starts on its own line.
- The locale list and the locale check come from the catalogue. A locale that is not shipped is an error, and the message names the shipped locales.
- The `report` flag is gone. `-v` and `--verbose` print the report, and they no longer share a letter with the version flag.

## Fixed

- `swag -V` prints the version. Before this release the short form reached the input flag instead, and the command asked for `--input`.
- `swag help` prints the help page. Before this release the parser refused the word `help` as an unexpected argument.
- `swag --help` shows every flag of the default command, and `swag interactive --help` shows the page of the new command.
- A run with an input file but no target reports a whole sentence. Before this release the message carried an unfilled `%s`.
- `swag --locale fr-FR` is refused with the list of shipped locales. Before this release it printed French, which no longer ships.
- The cover suite reaches 100 percent of statements again after the new reader and writer branches. The TTML and WebVTT writers are tested on every write call. A failure at the body, at the block, or at the closing tags then surfaces.

## Notes

- The interactive command reads one answer per line, so it works on a pipe as well as on a terminal. Vim inspired keybinds and a TOML configuration file are scoped to v0.9.0.
- A batch run reads each input once and converts the document into every named target, so the file read does not repeat per target.
- The preview is a best effort. It emits ANSI truecolour when the terminal carries colour, and it falls back to the hex value of a colour when the terminal does not.
- A `--strict-compat` flag is scoped to v0.9.0. It turns the integrity block off, so a write stays inside the original specification of the target format. The block stays on by default, because a plain format that ignores the block still reads correctly.
- Kdenlive carries no integrity block, because the format is a strict JSON array. Its writer reports the loss, and a conversion through JSON1 keeps the content.
- All nine reader fuzz targets pass a short run with no crash. [The testing notes](../testing.md) cover the fuzz targets.

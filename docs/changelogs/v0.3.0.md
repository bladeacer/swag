# v0.3.0: the YouTube pair

The YouTube pair: YouTube Timed Text (YTT) and SRV3 in and out, with the platform quirks that the upload path expects.

## Added

- YouTube Timed Text (`internal/formats/ytt`). The reader maps pens, window styles, window positions, ruby groups, and karaoke offsets onto the intermediate representation. The writer deduplicates pens and emits the head in increasing id order.
- The YouTube upload quirks on write, each with a test. The writer snaps a font outside the allow-list to Roboto, and remaps the font scale where `scale = 1 + (sz/100 - 1)/4`. It caps opacity at 254, shifts white to `#FEFEFE`, and lifts dark text to `#010101`. It writes a zero-width space between runs, and bumps a zero-duration karaoke segment. It adds the italic prefetch space, the shadow space, and the multi-shadow line layering.
- SRV3 (`internal/formats/srv3`) reader and writer. SRV3 shares the pen model of YTT, so the package reuses the ytt reader and writer and keeps its own registry name and extension.
- The font allow-list in `internal/formats/ytt/fonts.go`. The file is the single font table of the project. A font outside the list snaps to Roboto, and the writer records the loss.
- Karaoke normalisation in `internal/model`. `NormaliseKaraoke` bumps a zero-duration segment by one millisecond and orders the segments. Tests cover both rules.
- Sample-driven end-to-end tests. `scripts/fetch-samples.sh` pulls the upstream YTSubConverter sample file into the ignored `testdata/upstream/` directory. The tests skip when the file is absent, so the repository stores no upstream data and the clean-room statement stays true.
- The coverage badge rendered to `coverage.svg`, with a `make coverage-svg` target. The README badges follow the `ocd` project.
- A `make samples` target that pulls the upstream sample file.

## Changed

- The registry in `pkg/sub` gains `ytt` and `srv3`. Content detection reads a `<timedtext>` root element before the SubRip check, because an XML comment terminator is also a SubRip timing separator.
- The release configuration moves to `.goreleaser.yml` in the `ocd` style. A version tag now publishes the release instead of a draft release.

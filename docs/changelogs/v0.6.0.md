# v0.6.0: ASS tag closure and new formats

This release closes the ASS feature list of YTSubConverter. It reads and writes the Aegisub overrides that the intermediate representation (IR) can express, and it documents the full list. The same release adds the TTML, WebVTT, Kdenlive, and JSON1 formats, and reviews the loss report of every format.

## Added

- `internal/model`: span overrides for shadow distance (`ShadowDepth`), strikeout (`Strikeout`), and glyph scale (`ScaleX`, `ScaleY`). The resolved span carries the effective values.
- `internal/formats/ass`: the reader and the writer handle the Aegisub tags `\shad`, `\xshad`, `\yshad`, `\a`, `\s`, `\fscx`, and `\fscy`.
- `\ytchroma` custom colours and alpha. The IR chroma carries a colour list and an alpha channel, and the writer emits the long argument form.
- The `\ytkt` cursor forms. The reader keeps the `LCursor` and `RCursor` side, the cursor tags, and the animated frames. The writer emits the static, tagged, and animated forms.
- `internal/formats/ass/testdata/overrides.ass`: a round-trip fixture for the new overrides.
- `internal/formats/ttml`: a reader for the YouTube TTML dialect and a writer for general TTML. The reader maps named styles, regions, inline runs, and `begin` karaoke timing. The writer emits the document styles, one region per cue placement, and the inline spans.
- `internal/formats/vtt`: a WebVTT reader and writer. The reader accepts the signature, cue ids, and note blocks, and it maps the `align` and `position` settings and the inline tags. The writer emits the settings and the inline tags.
- `internal/formats/kdenlive`: a reader and writer for the subtitle track JSON of Kdenlive. Each element carries a layer, a start position in seconds, and an ASS event line.
- `internal/formats/json1`: a versioned lossless exchange format. It carries the whole IR, so a file keeps every feature across a tool boundary.
- [The ASS support page](../ass-support.md): the YTSubConverter ASS feature list mapped onto the IR fields and the tests.
- [The loss report review](../loss-report.md): the degradation of every format in the support matrix.

## Changed

- [The architecture page](../architecture.md): the package tree, the IR field list, and the format matrix name the new formats. The ASS tier lists name the new tags.
- [The format notes](../formats.md): the ASS section names the new tags, and the new formats gain their own sections.
- [The documentation index](../index.md): links the ASS support page, the loss report review, and the new format sections.
- The cross-check suite covers every shipped writer. It now asserts the loss report of the WebVTT, TTML, Kdenlive, and JSON1 writers as well, and the chain suite runs one fixture per reader.

## Fixed

- The comment headers of the ASS fixtures use a colon instead of an em-dash. [The contributor rules](../../AGENTS.md) ban the em-dash.

## Notes

- The reader maps `\xshad` and `\yshad` onto the one shadow distance of the IR, so the tag that appears last wins.
- The writer emits `\an` for an alignment, because the IR carries a numpad anchor.
- A chroma with more than one offset keeps a loss note, unless the offsets form the spread that the argument form rebuilds.
- The TTML reader covers the YouTube dialect. A document outside that dialect can degrade on read.
- The WebVTT reader keeps the spoken text of a voice span and drops the span, because the IR carries no voice field.

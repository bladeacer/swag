# v1.0.0: stable

The first stable release. It freezes the public API of `pkg/sub`, adds the browser demo, and records a performance audit. The command line now styles the help page with the same theme as its messages.

## Added

- The WebAssembly build, `cmd/swag-wasm`, which exposes the conversion of `pkg/sub` to a browser page. [The demo page](../demo/index.html) converts a document without an upload, and the release archive carries the build. [The migration guide](../migration.md) records the new target.
- [The performance audit page](../performance.md). It records the tools, the test machine, the numbers of every format, the bottlenecks, and the open items.
- [The migration guide](../migration.md) from YTSubConverter workflows. It maps each command, the reverse conversion, the shadow types, and the karaoke settings onto `swag`.
- The release archive for `js/wasm`. [The GoReleaser configuration](../../.goreleaser.yml) no longer skips the build.
- The SemVer guarantee for `pkg/sub`. [The library guide](../library.md) freezes the surface at v1.0.0, and a breaking change arrives only at v2.0.0.
- The `keybinds` table of the configuration file, which now takes a list of key tokens for each action. The tokens allow a modifier in any order, a single upper-case letter for shift, a repeated modifier, and several keys in one binding. [The configuration page](../configuration.md) records the notation.
- The timeout reader of the interactive mode. A terminal reads one key at a time in raw mode, so a binding fires as soon as its last key arrives, and a short pause ends a key sequence that carries no match. A pipe or a script keeps the line prompt. [The usage page](../usage.md) records the two paths.
- The benchmarks of the configuration decode and the keybind engine, with a `make bench-all` target. [The performance audit](../performance.md) records the results.
- The cached merge of the two configuration files. A run that resolves the global file and the working directory file twice serves the second lookup from the kept result, so the merge runs once. [The performance audit](../performance.md) records the cost of the cached pair.

## Changed

- The help page renders through the pterm theme, and the banner, the prompts, and the help share one palette. `swag --help` and the command output now look like one program, with one accent colour and no box. [The usage page](../usage.md) shows the flags.
- The `keybinds` table takes a list of key tokens. Replace each earlier string value with a list, for example `accept = ["<leader>", "a"]`. A string value is no longer read, and the tool reports the type error.
- The default configuration file shows the built-in defaults as active entries. Every fixed setting carries its built-in default value, and the `jobs` count stays absent because its default follows the machine. The file therefore changes no behaviour until you edit it. [The configuration page](../configuration.md) links [the default file](../../swag.toml).
- A broken configuration file now names the file in the error, beside the line that TOML reports. [The configuration page](../configuration.md) records the handling.
- The two deferred format cells carry issue links. FCPXML captions and SCC/CEA-608 stay stretch goals, and each one links its issue in [the architecture page](../architecture.md).
- The performance audit now runs the command line through `hyperfine`, `strace`, and `perf` beside `pprof` and `go tool trace`, and it fills the missing SubRip conversion cell. [The performance audit page](../performance.md) records the wall time, the syscall counts, the counters, and the profiles of a conversion.

## Fixed

- The readers allocate less. The SubRip span splitter appends into the span slice of the cue, the SubRip counter test skips the parser on a text line, the SubRip and SBV parsers find the colons instead of splitting, and the YouTube reader pre-sizes its slices. The SubRip parse allocates half as many objects, and the YouTube pair allocates fewer bytes. [The performance audit](../performance.md) carries the numbers.
- The WebVTT reader and writer build their entity replacer once. The earlier code built a replacer for every cue, which cost time and memory. The parse is about two and a half times faster, and the render is about three times faster. [The performance audit](../performance.md) carries the numbers.

## Notes

- The module keeps 100 percent statement coverage. `make cover-verify` enforces the floor.
- A caller that holds to the list in [the library guide](../library.md) keeps working across every v1 release.
- The browser demo needs the `swag.wasm` and `wasm_exec.js` files. `make wasm` builds the pair into `docs/demo/`, and the release archive carries them.
